# Как устроен агент

Техническое описание системы. Задание — [TASK.md](../TASK.md), результаты экспериментов — [EXPERIMENTS.md](EXPERIMENTS.md),
ход разработки — [DEVLOG.md](../DEVLOG.md), неоднозначности задания и принятые решения — [QUESTIONS.md](../QUESTIONS.md).

## 1. Обзор

Автономный агент управляет TurtleBot3 Burger в Gazebo (ROS 2 Jazzy, мир `turtlebot3_world` без изменений).

**Что агент знает:**
- карту стен (`turtlebot3_navigation2/map.yaml`);
- базу;
- свой заряд;
- вид модели датчика образцов.

**Чего не знает:**
- где образцы;
- где дорогой пол;
- где опасные зоны;
- что поменяется в сценарии hard.

| Уровень TASK.md | Где реализовано |
|---|---|
| 0. Среда | `launch/sim.launch.py`, `did.launch.py` (одна команда), свой судья `nodes/judge_node.py` |
| 1. Навигация | `core/costmap.py`, `astar.py`, `path_utils.py`, `controller.py`, `navigator.py`, `localization.py` |
| 2. LLM-планировщик | `core/llm_planner.py` (подцели по миссии), `core/llm_scientist.py` (стратегия научного агента) |
| 3. Научный цикл | `core/science.py`: поиск по датчику, цена грунтов по батарее, журнал гипотез |
| 4. Адаптация | `core/science.py`: смена грунта, опасные зоны, сбой датчика; база знаний между миссиями |

```
Gazebo (turtlebot3_world)
   │ /odom /imu /scan /clock                                   ▲ /cmd_vel (TwistStamped)
   ▼                                                           │
did_agent ─────────────────────────────────────────────────────┘
   Planner ──подцели──► MissionExecutor ──поездки──► Navigator (A* по карте стоимостей + регулятор, стоп по лидару)
   science | llm | scripted | manual    бюджет батареи      DeadReckoning (одометрия + IMU) → TF map→odom
   ├─ ScientificPlanner: SampleSearch · TerrainLearner · SensorTracker · LabJournal ── knowledge.json
   └─ LLMScientist (по желанию): журнал + варианты → выбор стратегии (ai.mai.ru, асинхронно)
   │ /did/collect, /did/finish (Trigger)
   ▼
did_judge — батарея, датчик образцов, столкновения, штрафы, скрытые события; поза — истинная, из Gazebo
   └→ /did/battery /did/sample_sensor /did/score /did/events
Пульт (localhost:8080) и RViz — карта, робот, лидар, путь, знания агента, журнал, решения LLM; цели мышью
```

**Принципы:**
1. **Логика — чистый Python без ROS** (`core/`), узлы ROS (`nodes/`) — тонкие обёртки. Логика тестируется за секунды, офлайн-симулятор
   (`core/offline_sim.py`) прогоняет миссию без Gazebo теми же модулями. Отдельный тест падает, если в `core/` появится импорт ROS.
2. **Подцель — граница между «кто решает» и «кто исполняет».** Подцели: `explore | goto | collect | return | finish | wait`.
   Любой планировщик (научный, LLM, фиксированный, оператор) выдаёт их в одном формате.
3. **Страховка заряда в исполнителе**, независимо от планировщика: поездка разрешена, если (туда + домой) × расход × 1,3 + 1 ≤ заряд.
4. **LLM не считает геометрию.** Алгоритм даёт модели посчитанные варианты, модель выбирает по id и объясняет. Ответ проверяется кодом.
5. **Судья считает по истинной позе из Gazebo**, агент — только по своим датчикам.

## 2. Карта, путь, движение

- **Карта** 384×384 клеток по 5 см. Совпадение с координатами Gazebo проверено по 9 столбам ({−1,1; 0; 1,1}², точность < 4 см).
- **Карта стоимостей.** Цена клетки = отступ от стен × цена грунта × риск.
  - Запрет — 0,2 м от центра робота до препятствия.
  - Полоса 0,2–0,35 м у стен — двойная цена.
  - Слой грунтов и слой риска заполняет научный агент.
- **A\*** — 8-связная сетка без срезания углов у препятствий, ~10 мс на всю арену. Путь сжимается до 3–10 отрезков; срезка — только если не дороже.
- **Регулятор** работает на 20 Гц:
  - ограничения Burger — до 0,22 м/с, плавный разгон;
  - при угле на точку больше 0,6 рад — разворот на месте;
  - замедление у цели;
  - по лидару: замедление ближе 0,35 м, стоп ближе 0,16 м;
  - нет продвижения 15 с — новый путь (до 3 раз).
- **Положение:** путь — по колёсам, курс — по IMU. Ошибка у образца упала с 0,28 до 0,05 м. Агент публикует `map→odom`.

## 3. Судья и сценарии

Свой судья по интерфейсу TASK.md:

| Топик / сервис | Что делает |
|---|---|
| `/did/battery` | заряд (старт 60); тратится 1,0 на метр × множитель грунта + повороты + простой |
| `/did/sample_sensor` | `exp(−d/0,7) + N(0; 0,03)` до ближайшего несобранного образца, без направления |
| `/did/score` | состояние и счёт (координаты не раскрывает) |
| `/did/events` | `collision`, `false_collect`, `hazard_hit`, `sample_collected` |
| `/did/collect` | успех, если образец ближе 0,30 м (+10), иначе −2 |
| `/did/finish` | конец прогона; на базе — бонус 0,1 × остаток заряда |

**Генератор сценариев по seed:**
- easy / medium / hard — 3 / 5 / 7 образцов и 1 / 3 / 4 зоны грунта (×2…4);
- в hard добавляются опасная зона и три скрытых события: смена грунта (20–40 с), новая опасная зона (35–60 с), сбой датчика (45–75 с, 40 с).
  Временные решения по неясностям задания — в QUESTIONS.md.

## 4. Научный агент (`planner:=science`)

### 4.1. Поиск образцов: датчик как дальномер
Показание `s` даёт расстояние до ближайшего несобранного образца: `d = −0,7·ln s`.
- **Усреднение.** Замеры усредняются по 5 (≈ 0,1 м пути). Шум оценивается робастно (по медиане отклонений).
- **Слабый сигнал** с запасом 3,5σ **исключает** круг арены: «ближайший образец дальше d».
  Кандидаты — точки свободного пола с шагом 0,1 м; исключённые не рассматриваются.
- **Сильный сигнал** (≥ 0,3) — гипотеза S «образец около (x; y)». Положение — минимум суммы квадратов невязок модели по замерам рядом.
- **Проверка:** подцель `goto` → `wait` 1 с (3 с при сбое датчика) → среднее ≥ exp(−0,3/0,7) ≈ 0,65 → `/did/collect`.
  Не вышло — оценка уточняется; после 6 попыток гипотеза опровергнута.
- **Разведка:** точка с наибольшей неисследованной площадью в радиусе 0,7 м, с поправкой на расстояние. Цель вычеркнута по дороге — поездка прерывается.

### 4.2. Цена пола по батарее
- **Расход на метр.** Путь режется на прямые отрезки по 0,2 м; на каждом считается расход на метр. Отрезки с поворотом больше 0,35 рад отбрасываются.
- **k — расход на обычном полу:** медиана всех отрезков (гипотеза T1).
- **Зоны.** Для клетки 0,25 м: `μ = медиана расхода / k`. Клетки с μ ≥ 1,35 объединяются в зону и дают гипотезу T «участок дороже ×μ».
  После 6 замеров она подтверждена и попадает в слой грунтов карты стоимостей.
- **Неизмеренный пол** оценивается выученным приоритетом: доля дорогих клеток × их избыток.

### 4.3. Адаптация
| Изменение | Признак | Реакция |
|---|---|---|
| Смена грунта | μ подтверждённой зоны ушёл > 30 % | статус «изменилась», карта обновлена, маршрут (и путь домой) перестроен |
| Опасная зона | штраф `hazard_hit` | гипотеза H, круг 0,55 м в слое риска (×50), перепланирование |
| Сбой датчика | шум > 3× базового | гипотеза D, ожидание 3 с, шире интервалы; затем «датчик восстановился» |
| Мало заряда | возврат по карте стоимостей × 1,3 + 2 | домой; если объезд опасной зоны не по заряду — напрямую (запись в журнале) |

### 4.4. Решения и перепланирование
**Выбор подцели**, по приоритету:
1. очередь;
2. режим «домой»;
3. все образцы собраны (`samples_total` из `/did/score`);
4. заряда только на возврат;
5. есть оценка образца → поиск;
6. разведка (с проверкой бюджета).

**Текущая поездка прерывается, когда:**
- появился сильный сигнал;
- цель разведки уже исключена;
- оценка образца сдвинулась > 0,25 м;
- изменилась карта стоимостей;
- пришёл штраф;
- проверка раз в 2 с показала, что заряда хватает только на возврат;
- пришёл выбор LLM.

После прерывания исполнитель берёт новую подцель, A* строит новый путь.

### 4.5. Журнал эксперимента и база знаний
- **`LabJournal`** — гипотезы (статусы: проверяется / подтверждена / опровергнута / изменилась) и ход эксперимента.
  Публикуется в `/did_agent/lab`, сохраняется в `runs/<время>_lab.md`, показывается на пульте.
- **`runs/knowledge.json`** — k, расход по клеткам, опасные зоны, гипотезы о грунтах. Следующая миссия с `knowledge:=runs/knowledge.json`
  загружает их как гипотезы и перепроверяет.

## 5. LLM

- **`planner:=llm` (уровень 2).** Модель по миссии и состоянию выбирает цели, порядок и момент возврата среди вариантов,
  посчитанных алгоритмом (A* + точное ДП по подмножествам). Ответ — JSON-план. Перепланирование: план выполнен,
  сбой подцели, штраф, переезд дороже прогноза в 1,4 раза.
- **`planner:=science llm:=true` (LLM-советник).**
  - **Когда зовут модель:** старт, сбор образца, зона подтверждена или изменилась, штраф, заряд ниже 50 % и 30 %, сектор исследован.
  - **Что она видит:** миссию, состояние, гипотезы, последние записи журнала и варианты — 6 секторов арены (неисследованная доля,
    ожидаемые образцы, цена «туда и домой» по выученной карте) плюс HOME.
  - **Что отвечает:** `{"thought", "choice", "hypothesis"}`.
  - **Как работает вызов:** асинхронно, робот продолжает разведку.
- **Обработка ошибок** (обоих режимов): проверка id, бюджета и формата; текст ошибки уходит модели на повтор; затем резервный выбор алгоритма.
  Без ключа или сети миссия идёт без модели.
- **Модель:** `deepseek-v4.1-flash` (ai.mai.ru), выбрана из 6. Ключ — только в `.env` (в `.gitignore`).
- **Почему модель не считает геометрию.** Пробовали дать координаты и «обойди зону»: 0 из 6 моделей ответили (37–77 с рассуждений).
  С таблицей стоимостей от A* ответили 6 из 6 за 5–7 с. Перебор комбинаций тоже вынесен в алгоритм: 4,5 с вместо 3 × 30 с без ответа.

## 6. Пульт и визуализация

`./scripts/control_panel.sh`, http://localhost:8080 (только 127.0.0.1):
- **Управление:** запуск и остановка с выбором сценария, режима, заряда, seed и модели.
- **Карта:** робот, лидар, путь A*, знания агента (неисследованная область, найденные зоны, опасности, оценка образца) и вид судьи.
- **Метрики:** заряд с графиком, счёт.
- **Вкладки:** «Журнал» (гипотезы со статусами), «LLM» (решения и объяснения модели), «События».
- **Работа мышью:** клик — цель, Shift+клик — точка маршрута (перехват управления оператором).

RViz показывает то же маркерами (`rviz/did.rviz`).
